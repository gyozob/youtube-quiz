# AGENTS.md

Personal Android app: pauses YouTube on a timer and shows a full-screen quiz
overlay. Sideloaded, never Play Store. See `README.md` for setup and
`requirements.md` for the original spec.

## Build and test

The toolchain is portable, installed by `tools\setup-toolchain.ps1` (no admin
needed). That script sets `JAVA_HOME`/`ANDROID_HOME`/`PATH` at user scope,
which only reaches **new** terminals — in the shell that ran it, or any shell
where Gradle cannot find a JDK, activate it first:

```powershell
. .\tools\activate.ps1            # generated by setup-toolchain, gitignored
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

`tools\run.ps1` builds, installs to a connected phone and tails logs.

**Keep lint at 0 errors** — `lintDebug` aborts the build on any error (AGP
default). One cosmetic `Overdraw` warning on `overlay_quiz.xml` is a known
false positive.

## Non-obvious constraints

Breaking these produces confusing failures, so check before changing versions:

- **AGP 9 supplies Kotlin itself.** Do not add `org.jetbrains.kotlin.android`;
  applying it is a hard error.
- **compileSdk must be 37+ and AGP 9.1+.** Current AndroidX requires both. The
  8.x line cannot build this project.
- **`sdkmanager` is a deprecated shim that lies.** It mis-parses the
  `platforms;android-37` form and **exits 0 having installed nothing**. Use the
  `android` CLI with slashes — `android sdk install platforms/android-37.2` —
  and verify the files landed rather than trusting the exit code.
- **`local.properties` must escape both `\` and `:`** or lint rejects it:
  `sdk.dir=D\:\\path\\to\\sdk`.
- **No hardcoded toolchain paths.** `tools\toolchain.ps1` resolves the location
  (arg → `YTQUIZ_TOOLS_ROOT` → `ANDROID_HOME` → folder beside the repo).

## Architecture

```
YouTubeWatchService (AccessibilityService)   <- foreground detection AND the timer
  +- MediaControl        audio focus and/or media key events
  +- OverlayController   TYPE_APPLICATION_OVERLAY window, 3 image cards
  +- AudioPlayer         question/feedback clips, serialised
QuizRepository -> SQLiteOpenHelper + images/audio in internal storage
ui/  Compose settings screens (Setup / Images / Questions / Sounds)
```

Decisions that look wrong but are deliberate:

- **The timer lives in the accessibility service**, not a foreground service.
  The system keeps accessibility services alive, which avoids a permanent
  notification and Android 14 FGS-type rules. Do not "fix" this.
- **Plain `SQLiteOpenHelper`, not Room.** Deliberate: it removes KSP and a
  class of version-alignment breakage. Do not reintroduce Room.
- **The overlay is XML/`View`, not Compose.** Compose in a `WindowManager`
  window needs manual `ViewTree*Owner` plumbing.
- **The overlay swallows Back** (a requirement). The 3-second top-left
  long-press escape hatch is the only way out — never remove it.
- **`PauseStrategy` has three options on purpose.** YouTube is not obliged to
  pause on transient audio-focus loss, so the fallback path must stay.
- **Events from our own package are ignored** in `onAccessibilityEvent`,
  otherwise showing the overlay reads as "the user left YouTube".

## Conventions

- Single log tag: `YTQuiz`. Check with `adb logcat -s YTQuiz:V`.
- Tags are trimmed and lowercased on the way in (`normalisedTag`).
- A tag needs 3 images + 1 question to be playable; unusable tags are skipped,
  not treated as errors.
- Deleting an image cascades to its questions; delete the files too, the FK
  only removes rows.
- Add dependencies sparingly — this builds with no IDE to repair conflicts.

## Testing reality

`app/src/test` covers the pure logic only: round selection, interval snapping,
tag readiness. Keep that green.

Everything that matters most — overlay rendering, audio focus, YouTube's
reaction, accessibility binding — **can only be verified on a real device**.
Do not claim those work without logs showing it.

When something fails on-device, add logging and read it. A past bug
(`decodeScaled` returning null because the elvis bound to `use {}` rather than
`openInputStream`) was invisible because the failure path returned a silent
null; guessing cost far more than one log line would have.

Two device-testing traps:

- **Never script `adb shell input` while a human is using the phone.** Blind
  taps land in whatever is on screen; this once wandered into Settings and
  toggled an unrelated accessibility shortcut.
- **Permissions must be granted by hand** on the device. Granting overlay or
  accessibility over adb is usually blocked, and is the user's call anyway.
